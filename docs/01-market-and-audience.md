# Анализ рынка и целевой аудитории

## 1. Актуальность

Цифровизация экономики и рост онлайн-торговли повышают требования к точности и скорости складских процессов. Крупные ERP-решения недоступны малому и среднему бизнесу по стоимости внедрения и сложности сопровождения. Компании продолжают вести учёт в Excel или бумажных журналах, что не обеспечивает целостности данных, не поддерживает бизнес-логику склада и не масштабируется[reference:0].

## 2. Целевая аудитория

| Сегмент | Характеристика | Ключевая потребность |
|---|---|---|
| Малый и средний бизнес | Нет ИТ-отдела, ограниченный бюджет | Доступная WMS с низким порогом входа |
| Интернет-магазины | Растущая номенклатура, несколько каналов продаж | Актуальные остатки и быстрый поиск товара |
| Логистические стартапы | Гибкие процессы, частое изменение структуры склада | Настраиваемая иерархия склада |

## 3. Обзор существующих решений и их недостатков

Для обоснования ниши SmartStock проведён анализ трёх категорий решений, которые использует целевая аудитория: Excel/бумажный учёт, ERP-системы и специализированные WMS для малого и среднего бизнеса.

### 3.1. Excel и бумажный учёт

Excel остаётся самым доступным инструментом на старте, но его ограничения становятся критическими при росте бизнеса.

| Преимущества | Недостатки |
|---|---|
| Доступен на каждом ПК, не требует затрат на внедрение | Высокий риск ошибок при ручном вводе|
| Гибкость настройки под свои процессы| Формулы можно случайно удалить или заменить |
| Возможность автоматических расчётов | Не подходит для больших объёмов данных |
| | Нет разграничения прав доступа между сотрудниками |
| | Одновременное редактирование приводит к повреждению данных и откату к предыдущей версии|
| | Отсутствие актуальных остатков в реальном времени |

**Вывод:** Excel — это не система управления складом, а электронная таблица. Он не хранит бизнес-логику, не поддерживает роли и не масштабируется. При росте номенклатуры и числа сотрудников Excel неизбежно становится источником ошибок.

### 3.2. ERP-системы (SAP, Oracle, Acumatica)

ERP-системы покрывают широкий спектр бизнес-процессов, но их внедрение сопряжено с высокими затратами и сложностью.

| Преимущества | Недостатки |
|---|---|
| Мощная функциональность и аналитика| Медленное внедрение и высокая стоимость настройки |
| Интеграция с финансами, закупками, производством | Изменение настроек требует дополнительной оплаты |
| Поддержка крупных предприятий | Сложность интеграции с другими системами |
| | Требуется длительное обучение персонала |
| | Внедрение может затягиваться и выходить за бюджет, особенно у малого бизнеса |

**Вывод:** ERP-системы избыточны для малого склада. Они решают задачи крупного предприятия, но требуют ресурсов (финансовых, временных, человеческих), которых у целевой аудитории SmartStock нет.

### 3.3. Специализированные WMS для малого и среднего бизнеса

На рынке присутствуют WMS-решения, ориентированные на SMB. Рассмотрены типичные представители (Flowtrac, SnapFulfil, Nemika WMS) — не как конкретные конкуренты, а как иллюстрация класса решений и его ограничений.

| Преимущества | Недостатки |
|---|---|
| Ориентированы на SMB, ниже порог входа | Внедрение может быть плохо организовано: заявленные требования не выполняются месяцами |
| Проще в освоении, чем ERP | Ограниченная гибкость: изменения требуют обращения в поддержку |
| Быстрый запуск у некоторых вендоров (от 10 дней)| Стоимость настройки под индивидуальные процессы может быть значительной |
| Облачная модель снижает затраты на инфраструктуру | Для складов с небольшим количеством SKU функционал может быть избыточным |
| | Требуется стабильное интернет-соединение |
| | Кастомизация может быть дорогой |

**Вывод:** WMS для SMB — наиболее близкая категория к SmartStock. Однако существующие решения либо слишком дороги в настройке, либо недостаточно гибки, либо требуют стабильного интернета и не решают проблему «склад без структурного представления» из коробки.

### 3.4. Сравнительная таблица

| Критерий | Excel | ERP | WMS для SMB | **SmartStock (целевое позиционирование)** |
|---|---|---|---|---|
| **Стоимость внедрения** | Низкая | Высокая | Средняя | **Низкая** |
| **Скорость запуска** | Мгновенно | Месяцы | Дни–недели | **Дни** |
| **Структура склада (ячейки)** | Нет | Есть | Часто есть | **Есть (гибкая иерархия)** |
| **Актуальные остатки** | Нет | Есть | Есть | **Есть** |
| **Разграничение ролей** | Нет | Есть | Есть | **Есть (RBAC)** |
| **Обработка исключений (брак, несоответствие)** | Вручную | Сложно | Зависит от вендора | **Встроена в процессы** |
| **Порог входа для сотрудника** | Низкий | Высокий | Средний | **Низкий** |

**Общий вывод:** существующие решения либо слишком дороги и сложны (ERP), либо не покрывают складскую специфику (Excel, универсальные таблицы), либо, будучи WMS для SMB, требуют значительных затрат на кастомизацию и не решают проблему структурного представления склада «из коробки». **SmartStock занимает нишу:** доступная WMS с гибкой иерархией склада, встроенной обработкой исключений и низким порогом входа — без необходимости в ИТ-отделе и многомесячного внедрения.
