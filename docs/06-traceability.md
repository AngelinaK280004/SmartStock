# Матрица трассировки — SmartStock

Связывает требования из `docs/05-requirements.md` (FR-01…FR-16, NFR, BR) с источниками (проблемы пользователей, процессы, сущности данных) и проверяемыми критериями приёмки (из `05-requirements.md`).

## 1. Легенда

- **Проблема** — номер из `docs/02-problems-and-goals.md` (№1–№6).
- **Процесс** — `IDEF0 A1/A2/A3`, `ARIS <ветка>`, `BPMN <ветка>` из `docs/03-process-modeling.md`.
- **Сущность** — таблица из `docs/04-data-model.md` (UPPER_SNAKE_CASE, как в ERD).
- **Критерий** — ссылка на раздел 6 `05-requirements.md` или на метрику в `docs/07-metrics.md`.

## 4. Бизнес-правила (BR)

| ID | Правило | Связано с FR/NFR | Где соблюдается | Критерий проверки |
|---|---|---|---|---|
| **BR-01** | Действия с документами и остатками — только по ролям в зоне ответственности | FR-16, NFR-SEC-01 | API | Gherkin 6.15 |
| **BR-02** | `PRODUCTS.quantity >= 0` | FR-05, FR-07, FR-13 | CHECK в БД (NFR-DATA-01) | Миграция + негативный тест |
| **BR-03** | `PRODUCTS.sku` уникален | FR-02 | UNIQUE-индекс (NFR-DATA-02) | Миграция + тест на дубликат |
| **BR-04** | Товар с дефектом или несоответствием не размещается | FR-03, FR-04 | Бизнес-логика | Gherkin 6.3, 6.4 |
| **BR-05** | Размещение не превышает `SHELVES.capacity` | FR-05 | Бизнес-логика | Gherkin 6.5 |
| **BR-06** | Каждая операция с остатком — в `TRANSACTIONS` | FR-06, FR-07, FR-08, FR-13 | Сервисный слой (NFR-SEC-03) | Проверка логов / интеграционный тест |
| **BR-07** | Отгрузка только при достаточном остатке | FR-13, FR-14 | BPMN «Отгрузка» | Gherkin 6.13 |
| **BR-08** | Инвентаризация создаёт корректирующую транзакцию, а не перезапись остатка | FR-08 | Бизнес-логика (NFR-DATA-03) | Gherkin 6.8 |
